# 1280×720 canvas input and UI regression

Godot 4.7.2 rendered run, 2026-10-14. The project uses a 640×360 logical canvas, a 1280×720 window, `canvas_items` scaling and integer scale mode. This is automated engine evidence, not a human playtest or M8 art acceptance.

## Result

- [Targeted test](../../game/tests/rpg-2-star-ocean-the-second_scifi-canvas-pointer-regression_m8-v01_20261014-195000-6e24b8a1.gd) passed with `CANVAS_POINTER_REGRESSION_OK`. It injects mouse events at **physical window pixels** through `Viewport.push_input(event, false)`; it does not emit button signals. A click at unscaled `(136,222)` missed the city destination; `(272,445)` hit its logical center and opened the city. The city back button at physical `(1148,62)` returned to the map. This verifies Godot's window-to-canvas pointer transformation in a real rendered window, though it is not a hardware mouse click.
- A physical D key event moved the city hero from `(340,253)` to approximately `(368.03,253)`. A physical E key event at the Liang Xu hotspot opened the interaction dialogue. Existing city navigation tests cover walking routes to all city hotspots.
- Initial 1280×720 screenshots exposed an English world-map header defect: the long help line ran into the Save button region. [English map copy](../../game/scripts/app_state.gd) was shortened to “Choose a destination · Travel takes no days”; the new regression checks the rendered help label's minimum width against the Save button position in both languages. The repaired [English map screenshot](../../outputs/rpg-2-star-ocean-the-second_scifi-canvas_ui-regression-map-en_m8-v01_20261014-195426-ed2a77fe.png) shows separation.
- Separate final actual Godot captures: [Chinese map](../../outputs/rpg-2-star-ocean-the-second_scifi-canvas_ui-regression-map-zh_m8-v01_20261014-195426-ed2a77fe.png), [Chinese city](../../outputs/rpg-2-star-ocean-the-second_scifi-canvas_ui-regression-city-zh_m8-v01_20261014-195426-ed2a77fe.png), [English map](../../outputs/rpg-2-star-ocean-the-second_scifi-canvas_ui-regression-map-en_m8-v01_20261014-195426-ed2a77fe.png), [English city](../../outputs/rpg-2-star-ocean-the-second_scifi-canvas_ui-regression-city-en_m8-v01_20261014-195426-ed2a77fe.png). I inspected all four at 1280×720. Their header buttons, destination labels, city markers and footer text are visible within the window; no other clipping was evident in these four states. The [machine receipt](../../outputs/rpg-2-star-ocean-the-second_scifi-canvas_pointer-regression-receipt_m8-v01_20261014-195426-ed2a77fe.json) records click coordinates, movement positions and capture paths.
- `M8_CITY_INTEGRATION_OK` passed headless. The existing world-map visual check also passed headless (`WORLD_MAP_VISUAL_CHECK_OK captures=0 buttons=3`); its exit reported two leaked ObjectDB instances, with no failed assertion. The rendered targeted test supplied the 1280×720 visual evidence.

## Scope

The only production change is the shorter English map help sentence. No scene flow, movement, visual registry, Game Bible acceptance counter or art approval was changed. Pointer mapping was tested through Godot's input dispatch at a 2× window size; operating-system mouse focus, other display scales, and full human play remain untested.

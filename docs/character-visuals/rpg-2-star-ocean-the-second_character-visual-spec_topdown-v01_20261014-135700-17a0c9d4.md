# 《世界之间》角色游戏内视觉规格 v0.1

**用途：** 52 个视觉版本共用的俯视探索生产基线。此规格是待运行样板复核的制作约束，不代表 52 组精灵已完成。来源画像保留人物身份、发型和服装参照作用；21:9 设定图不能直接缩小当作可玩精灵。

## 画布、朝向与动作

| 项目 | 首轮制作规格 |
|---|---|
| 游戏逻辑画面 | 640×360；普通窗口 1280×720 为整数 2 倍显示。以逻辑像素判断辨识度。 |
| 单帧工作格 | 透明 RGBA，32×48 **原生像素**。人物默认可见高度 38–42 像素，不依赖把千像素人像缩到 40 像素。体型特例可在 28–48 像素高调整，但必须在场景中对齐足底。 |
| 锚点 | 每帧固定 `(16,44)`，即靴底接地中心；脚下只占约 12×5 像素的世界碰撞／交互足迹。头发、背包、披风不改变世界坐标。阴影与地面接触提示独立绘制。 |
| 四朝向 | `south` 面向屏幕、`west` 向左、`north` 背向屏幕、`east` 向右；文件和数据 ID 使用同一顺序。不能把左右对称镜像作为默认：肩章、偏分、单侧辫、工具和披风方向均需核对。 |
| 每朝向交付 | 待机 1 帧＋行走循环至少 4 帧（接触、过渡、对侧接触、过渡），共每人最少 20 帧；每帧相同锚点。首轮方向静帧只是样板，**不算完成标准四方向精灵**。 |
| 插值 | 精灵使用 nearest filtering、整数像素定位；禁止线性缩小高分辨率概念图作为最终素材。像素块、轮廓线和 2–3 级明暗须按原生尺寸手工整理。 |
| 色彩 | 人物常态 20–32 个有效颜色为建议上限；确保头发和主体服装在城市暖石色、自然绿、魔法冷光等板块背景下分离。颜色不能是唯一身份提示。 |

## 角色身份保真

1. **先看头与肩的外轮廓：** 每人至少一个在 40 像素高度仍能看见的 2–4 像素形状锚点，如高马尾向外伸、梁序高盘发＋单侧银发、赵铃耳机、纪澄耳后剃短。仅变换眼色、细线或衣扣无效。
2. **再看板块与服装：** 主角男女共享茶绿围巾和社区菱形徽记，但男女发型和身形节奏必须分开；梁序用高领、石墨长外套和铜色圆扣。职业换装应改变衣着细节与装备，保留固定发型／头饰轮廓、肤色和稳定的角色专属色块。
3. **背面与侧面优先审：** 发型重复在背面最容易暴露。双辫、单辫、盘发、高马尾、剃侧背、短寸等要分配各自宽度和突出方向；外套、背包不能遮死其识别处。
4. **可玩五形象连贯：** 主角男、主角女、梁序、赵铃、纪澄的横向战斗图须沿用探索图的头型、主色和关键配件，战斗姿态可更宽、更夸张。战斗动画需涵盖待机、移动、攻击、防御、闪避、受击、倒下与个人技能，单张概念姿态不计入完成。

## 验收方法

- 在 Godot 实际 640×360 场景与 1280×720 窗口中检查，不以图片浏览器的放大图代替。五人同屏时先关掉名字标签，分别检查正、背、左右的发型／肩部／配件轮廓；在亮处、阴影、绿色植物和石砖背景都能辨认。
- 首轮城市样板须在真实科技城**暖色铺地与繁密建筑细节**前，靠至少两项不依赖名字的视觉线索区分主角男、主角女、梁序；例如头发外轮廓加一块稳定的服装／背包色块。必要时用 1 像素外缘明暗分离人物与铺地，但不能用恒定发光描边替代角色设计。三人四方向通过之前，不开始 52 人批量绘制。
- 把图像缩为人物 40 像素高后，若只能看到“深色人形”或主角男女／梁序必须靠文字标签区分，应退回原生像素重绘。检查最小可走间距、建筑前景遮挡、脚底是否落在可走区域，以及移动帧切换是否抖动。
- 通过单方向静帧只算“方向草案”；四方向待机和行走、运行画面、人工审查全部通过才可更新资产清单的对应 `runtime-sprite` 项。来源画像的 9/52 批准状态由用户先前审定，与精灵图验收是两个独立状态。

机器可读 ID 和路径见同分支 `game/data/character-visuals/` 中的 visual registry。第一轮 40 像素核对与失败项见配套 review。

# M8 角色画质规格 v0.2（提案，待用户验收）

本规格延续[640×360 尺度诊断](rpg-2-star-ocean-the-second_scifi-city_character-fidelity-direction_m8-diagnostic_20261014-150011-7bd426d2.md)，加入可重复的单人画质检查和真正的 1280×720 渲染实验。**这里的测试脚本不写 `project.godot`、正式场景、角色注册表或追踪器；每次在进程内显式选择渲染模式。**现有高画质男女主 PNG 是概念候选，尚未成为正式四向精灵，也未获用户美术批准。

## 实机证据

- 原游戏角色与 UI：[显式 `viewport` 渲染，实际纹理 640×360](../../outputs/rpg-2-star-ocean-the-second_scifi-city_native-scene-viewport-render_m8-v02_20261014-150426-71d043f7.png)；[同一城市显式 `canvas_items` 渲染，实际纹理 1280×720](../../outputs/rpg-2-star-ocean-the-second_scifi-city_native-scene-canvas-items-render_m8-v02_20261014-150435-6a5a1313.png)。两次窗口均为 1280×720。后者建筑细节和字体明显清晰，UI 布局与角色在场景中的相对位置保持一致；旧 32×48 角色仍然呈大块像素。
- 男主候选、同样约 72 逻辑像素高：[640×360 现行模式](../../outputs/rpg-2-star-ocean-the-second_scifi-city_protagonist-male-character-quality-h72_m8-v02_20261014-150127-12d6bdd1.png)；[1280×720 `canvas_items` 模式](../../outputs/rpg-2-star-ocean-the-second_scifi-city_protagonist-male-character-quality-h72-canvas-items_m8-v02_20261014-150306-6d4a7d65.png)。
- 女主候选、同样约 72 逻辑像素高：[640×360 `viewport` 模式](../../outputs/rpg-2-star-ocean-the-second_scifi-city_protagonist-female-character-quality-h72-viewport_m8-v02_20261014-150421-818cfbb5.png)；[1280×720 `canvas_items` 模式](../../outputs/rpg-2-star-ocean-the-second_scifi-city_protagonist-female-character-quality-h72-canvas-items_m8-v02_20261014-150202-a560b6ce.png)。两人都使用城市场景脚点 `(340,253)`，各自为单独截图，没有拼图。

`canvas_items` 在同一逻辑坐标下保留两倍物理采样密度；大尺寸候选的发型、面部、服饰层次与城市纹理一起变得更清楚。截图只验证静态渲染；窗口大小变化、输入映射、遮挡、性能、游戏全流程尚未回归。高分辨率概念图缩到目标高度仍可能出现杂纹、软边及暗色低透明度晕圈，不应作为最终像素精灵直接入库。

## 提议的角色成品规格

| 项目 | v0.2 目标 |
|---|---|
| 游戏坐标/输出 | 保持 640×360 逻辑坐标；拟采用 1280×720 `canvas_items` 原生渲染，实际切换须另行验证。 |
| 城市可见身高 | 普通同层角色约 72–80 逻辑像素，首个统一样本取 76。男女主与同层 NPC 共享尺度。 |
| 像素精灵试样 | 优先验证 `192×224` 透明画布、可见身体 `144–160` 源像素、脚点 `(96,208)`；节点缩放 `0.5` 逻辑倍数，在 1280×720 下形成每个绘制像素约一个屏幕像素。与 1× `96×112`/脚点 `(48,104)` 方案做实机视觉对照，再锁定规范。 |
| 取样与滤镜 | 角色最近邻；背景维持线性；角色在物理像素上对齐，不使用动画中不断变化的小数缩放。原图 1024–1536px 仅作设定与纹理参考，输出前须重新像素化、修轮廓和色块。 |
| 接地 | 每帧保持同一脚点及按脚底 y 排序。阴影独立绘制，先试低透明软椭圆约 28–40×6–14 逻辑像素，不烘焙进人物图。 |

## 单张候选验收流程

使用[单人 Godot 画质检查脚本](../../game/tests/rpg-2-star-ocean-the-second_scifi-city_character-quality-review_m8-v02_20261014-145832-792dea16.gd)，一次只载入一张透明 PNG；可传 `--candidate`、`--label`、`--height`、`--anchor-x`、`--anchor-y`，及可选 `--render-mode=canvas-items`。脚本把原城市角色临时隐藏，在固定城市脚点渲染候选和独立软阴影，生成**一张**实机 PNG 与同名 JSON 收据，不修改任何正式资源。当前模式对照另由[渲染模式实验脚本](../../game/tests/rpg-2-star-ocean-the-second_scifi-city_canvas-scale-experiment_m8-v02_20261014-150240-41cf0b96.gd)生成。

1. **透明与裁切**：检查四角完全透明、强可见像素不碰画布边；检查人物之外没有暗色矩形、旧背景残留和远离身体的低透明度碎点。收据统计 alpha 阈值 `64/255` 的边界、画布边缘强像素，以及低/中/近不透明像素数量。统计只能定位风险，不能自动判定画面干净。脚点须落在可见鞋底，鞋底不得悬在阴影上方或被遮住。女主概念图用 PNG 最底 y=1373 作脚点时，强可见身体结束于 y=1328，会留下约 2.5 逻辑像素偏差；当前 72 像素检查改用强可见鞋底 y=1328。
2. **轮廓与发型**：原尺寸下能凭外轮廓、发型、主服色和标志性配件分清人；边线应有有意控制的厚薄及光照，不靠统一厚黑框。暗衣服在深色路面、亮发丝在浅色铺地都应可辨。要人工检查男女主、梁序以及下一批角色并排的剪影差异。
3. **抗锯齿与像素簇**：新原生像素图须检查发丝、眼、衣缝、手指有没有沸腾的单像素噪点；半透明边缘只保留经过设计的过渡，不留自动缩图的灰色光晕。线性缩放概念图和最近邻缩图均只可作比例测试。
4. **方向与动画**：静态南向通过后，分别完成南/西/北/东四向；每向至少 2 帧待机、6 帧行走，核对脚点、体积、衣装层级、发型辨识和帧间节奏。战斗八动作属另一个镜头规格，不能以单张城市样本宣布其完成。科技区 5 个可用外观按 `5×4×8=160` 张探索帧估算，尚不含转职服装。
5. **城市场景遮挡**：放大角色后重看树冠遮挡、`city_hero_silhouette`、门口比例、交互标识与 NPC 标签；它们仍按旧人物尺度排布。现有城市碰撞和交互热点不能只凭截图推定正确。检查所有门口、上层道路、树下及贴近 UI 的位置，并用实际输入确认控制坐标没有受渲染模式改变。

**当前状态：** v0.2 是美术与技术方向提案。单张候选仅通过“可载入并可在真实城市截图”的技术检查；人物美术、四向/动画、运行性能和更改项目渲染模式均待后续验证与用户确认。测试用 `Image.load` 直读候选 PNG；未导入的资源可能在 Godot 打印仅适用于编辑器测试的警告，正式游戏须走正常资源导入。

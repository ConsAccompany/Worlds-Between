# 《世界之间》MVP 实施计划 v0.2：角色与场景画面纳入验收

## 原始目标与本次调整

完整游戏仍是 PC 单人、中英双语、2D 像素开放世界 RPG，以探索、伙伴招募、横向即时战斗和职业成长为核心。此前的 MVP 将美术视为占位资源，集中验证科技板块三地点的循环。现在 MVP 必须同时验证**角色形象与场景品质**：使用目前已创作的全部 51 位角色形象（主角男女两版共 52 份视觉身份），并让科技区可游玩场景达到《逸剑风云决》所代表的精致像素环境观感。这个目标是最终屏幕呈现的质量要求，不要求复刻其虚幻引擎 4 的具体制作技术。

《逸剑风云决》的官方商品页将其视觉描述为传统像素角色与 3D 景观、现代视觉效果的结合。本文据此把参考拆成可检验的层次、材质、光影、场景辨识度和角色融入度，制作《世界之间》自己的科技板块视觉语言。[官方视觉说明与画面](https://store.steampowered.com/app/1876890/Wandering_Sword/)

## 新 MVP 假设

一段科技区三地点、约 25–35 分钟的试玩，在可辨识的 51 人角色视觉库和达到参考品质的科技区场景中，能让玩家愿意探索、招募并带伙伴战斗。只有玩法循环与画面两项都通过实际试玩和画面审查，才算 MVP 完成。

## 包含范围

1. **保留已有可玩切片：** 世界地图上的科技城市、城外、遗址；三位可招募伙伴；三地勘察、线索关联、机械接敌／避战、城市汇报、双语、职业与存档基础。M1–M6 的技术验证保留，M7 的真实通关验收尚未完成。
2. **52 份角色视觉身份：** 主角男／女两版与 50 位伙伴，各有经审查的来源画像、在引擎内加载的角色展示图、可在游戏内查看的对应人物外观，以及统一规格的俯视探索形象。正式游玩仍只让科技区可用角色出场、招募和战斗；其他角色先在游戏内角色图鉴中作为美术预览，保持未解锁状态，不提前开放剧情或招募。
3. **四人可玩队伍美术：** 主角选定版本、梁序、赵铃、纪澄在当前三地点使用与其画像一致的探索精灵，战斗使用对应的待机、移动、攻击、防御、闪避、受击、倒下和个人技能表现。其他角色的战斗动作留待他们可游玩的阶段。
4. **环境质量：** 科技世界地图、城市、城外、遗址、三地六处勘察空间及独立战场都从几何占位画面升级为经过统一艺术指导的完成画面。每处有独特建筑、地表和可调查物，具备前中后层次、可读的光影与适量动态效果；场景仍保持俯视探索及横向平地战斗，不改变既定玩法视角。
5. **视觉一致性：** 角色与场景共享像素密度、比例、光源方向和调色原则；发型、轮廓、服装标识在游戏缩放下可辨；交互目标与敌人不会被装饰遮住。

## 暂不纳入本次可玩内容

其他四板块的可探索地图、全部 50 位伙伴的招募与战斗、20×5 职业全量、恋爱、终局主线和二周目。它们仍在完整游戏范围内。52 份角色视觉资产的制作不等于 51 人全部进入当前剧情。

## 当前素材基线

- 已有 **52 份 21:9 角色设定图**，覆盖主角男女两版与 50 位伙伴；清单中仅 **9 份标记为已验收**，其余仍是待审概念稿。
- 主角及少量核心角色另有方向和动作原型。这些图尚未统一像素网格、方向、锚点或逐帧尺寸，不能直接视作游戏内动画。
- Godot 当前可运行场景使用简化几何色块。M2 的城市和遗址画面只证明导航与交互，尚未达到新画质目标。
- 正式美术缺口以游戏圣经的资产清单为准；新增项目在完成审查前保持未勾选。

## 美术制作规格与验收

| 检查点 | 交付与判定 |
|---|---|
| 身份保持 | 52 份来源画像逐张核对发型、配色、脸部特征、轮廓、道具；未验收的概念图先修订再制作游戏精灵。主角两版都可在创建角色时预览。 |
| 游戏内可用 | 每位角色的展示图和四方向探索精灵可由稳定角色 ID 加载；图鉴可逐一预览 51 位角色，不出现缺图、错人、混用发型或角色比例跳变。 |
| 可玩角色动作 | 主角男女两版和科技区三位伙伴在探索与战斗中使用各自形象；动作锚点稳定、朝向正确，不以同一通用人偶替代。 |
| 场景完成度 | 科技地图、三个主场景、六个勘察空间和战场逐张与选定官方参考画面并排审查：丰富但有序的材质细节、空间深度、建筑与自然／机械物件层次、明确光影、适量动态效果、独立辨识度均通过人工审查。 |
| 可读性 | 在实际游戏的 1280×720 窗口和 1920×1080 全屏下，玩家可辨主角、伙伴、敌人、入口和调查点；中文／英文 HUD 不被背景吞没。若现有 640×360 逻辑画布限制细节，先调整画布与比例，再批量制作。 |
| 性能与交互 | 场景美术升级后仍能流畅移动，接敌到可操纵战斗的目标维持 1 秒内；交互碰撞、绕敌路线、存档位置和剧情触发不因美术重做而改变。 |
| 结果证明 | 每个目标场景保留实际引擎截图与逐项审查结果；两个新档、两种首访顺序完成 25–35 分钟真实试玩，并记录视觉与操作反馈。 |

画质对标以**完成的运行画面**判断，不以单张概念图、渲染图、自动截图或素材数量代替验收。项目不直接使用参考游戏的素材。

## 推荐制作方式

- **引擎：**继续使用当前 Godot 4.7.2 项目与 GDScript，先在一间科技城市场景做画面样板。可以用分层 TileMap、Y 排序、前景遮挡、法线／2D 光照、粒子和局部视差构成深度；以运行画面判断是否足够，不预先锁死渲染手法。
- **角色：**以已创作的 21:9 画像为身份参考，逐一制作独立的游戏内展示图和标准方向精灵。统一像素网格、足底锚点、视角和动作模板，再按角色修正头发、服装与关键物件；批量生成结果必须逐人检查。
- **环境：**先完成色彩与材质板、尺度图和一张场景样板，再扩展到三地点及六个勘察空间。科技板块要有自身的传统城市与适度先进科技，保留“能用就不换”的社会视觉原则。
- **数据：**用现有稳定角色 ID 映射来源画像、游戏内展示图、探索精灵与可玩角色战斗精灵；资源缺失时在制作检查中报错，避免发布时静默回退到占位图。

M7 玩法检查与 M8 美术样板可并行，但 **M9 不在两者完成前开始验收**。

## 主要风险与处理

1. **单人产能：**52 套方向精灵与高品质环境是显著扩大的 MVP 范围。先用一名主角、一名伙伴和城市样板验证像素比例、制作工时与画面方向，再沿相同规格批量生产；真实工时由样板结果估算。
2. **概念图无法直接动画化：**已有 21:9 图是身份依据，不是标准精灵表。独立拆图、统一朝向和逐帧校正需要专门制作与人工检查。
3. **2D 深度与参考的 3D 景观不同：**先以用户实际看到的画面为判定；若首张完成场景无法达到目标，再决定是否引入 Godot 3D 场景承载像素角色，而不是在全部地图完成后返工。
4. **视觉细节遮挡玩法：**美术审查同时检查路线、交互、敌人轮廓与战斗切换，不接受只在静态截图好看的场景。

## 尚待后续确定

- 第一张城市场景完成后，用运行截图确定是否需要 2.5D 场景技术；本计划暂以 Godot 2D 分层方案开工。
- 角色探索精灵最终像素格尺寸、帧数与调色板由样板在实际窗口中验证，不沿用未经验证的旧草案数值。
- 51 位角色中未验收的 43 份概念图逐张决定“直接批准、局部修订或重做”，不会自动把已有文件当作最终外观。

# 开放世界像素 RPG：MVP 实施计划 v0.1

**计划状态：**已制定，尚未开始游戏工程。每步只有达到验收标准才记为完成。本文是制作顺序，不修改已确认的完整游戏目标。

## 原始目标与验证问题

最终游戏是 PC 单人 2D 像素 RPG，以**探索世界、招募伙伴**为首要体验，包含俯视地图与场景、可绕过的可见敌人、极短转场的横向即时战斗、最多五人队伍、角色切换与 AI、升级转职，以及最终五板块／50 同伴／20 职业系列的规模。剧情细节留待角色与系统基础稳定后设计。

**MVP 假设：**一段 25–35 分钟的科技板块试玩，只要让玩家主动选择地点、发现可互动的人和线索、以不同方式招募伙伴，再带新伙伴进入有切换与指令的即时战斗，就足以判断这套核心循环是否值得扩展到完整开放世界。

**成功信号：**试玩者无需开发者解释，能从世界地图找到下一处可探索地点；至少主动尝试一次可选招募或发现；能理解“绕过敌人或接战”的选择；通过角色切换与伙伴 AI 完成战斗，并想继续去地图上的另一处地点。记录实际卡点与选择，不以好评数量替代观察。

## MVP 边界

### 纳入

- **地点：**仅科技板块的 1 个城市片区、1 个城外场景、1 个遗址室内场景；世界地图可点击三处，进入后主角自由移动，普通旅行不推进日期。地点难度固定，敌人在场景中可见、可绕开，离开并重进后重置。
- **角色：**可选男／女主角并自定义姓名；梁序作为主线导师、赵铃作为日常情境伙伴、纪澄作为短人物任务伙伴。三人都可以暂不邀请并回来招募。入队等级跟随主角，给出对应的职业与技能进度。最多五人上场的结构与 UI 存在，试玩内容提供主角加三位伙伴。
- **战斗：**固定大小的平地横向战场，无跳跃、地形或障碍机制。普通攻击、闪避、防御、能量消耗、角色即时切换；未操控者按少量“条件→行动”规则行动。暂停时仅当前操纵角色能选技能并给队友下临时指令；可切到全自动。常用技能快捷栏和暂停菜单可用。接敌到可操作控制的转场在开发机上以 1 秒内为暂定目标。
- **成长：**个人等级、经验和 JP；先实现剑术、枪械、战术、遗物 4 条职业系列各前 2 阶的最小技能集。主角四项天分均为 60；四项天分与 60 门槛按通用数据模型实现。等级 10 时必须做职业选择，允许留任／晋升／换系列，已学进度切回后保留；个人技能始终可用。等级与职业数据结构不设硬上限，MVP 内容只覆盖低级阶段。
- **状态与存档：**战后存活者 HP／能量各加其最大值的 20% 至上限；倒下者复活到 10%。升级回满。每场战斗后自动存档，另有手动存档；战败回主菜单并可读取。未上场随队角色得 25% XP／JP。
- **探索反馈：**遗址中一项可发现的线索记录和一段简短中英文文字，用来测试“探索有发现”；不实现完整考古解谜链。
- **语言与操作：**中文、英文 UI 与试玩文本；键鼠操作、可重新绑定的关键操作、基础设置与清晰的菜单提示。

### 暂不纳入

其他四个板块、完整主线与结局、50 人全量、20×5 职业全量、最终职业任务、恋爱与组合技、全套名声、完整考古系统、商会贸易、装备合成、日历推进、二周目、在线合作。它们保留在完整设计目标中，MVP 数据结构避免把角色数、职业数或板块数写死。

## 技术选择

- **引擎：**Godot 4.7.2 稳定版、GDScript、2D 场景与 TileMapLayer。选择理由是单人项目可直接在编辑器迭代俯视场景、战斗场景与 UI；官方文档支持以 AnimatedSprite2D 或 AnimationPlayer 使用独立帧或图集。[Godot 官方 4.7.2 发布信息](https://godotengine.org/article/maintenance-release-godot-4-7-2/)、[2D 动画文档](https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html)。
- **数据：**角色、技能、职业、招募条件与地点采用稳定 ID 的小型数据文件／Godot Resource；对话和 UI 字符串使用中英文键值，先保持格式简单。版本化存档，避免后续新增内容破坏已有存档。
- **素材：**现有 21:9 角色画像和透明动作稿作为视觉参考。它们尚未统一像素网格与逐帧锚点；MVP 仅对试玩角色制作可运行的固定格精灵，不把概念动作稿直接当成动画帧。
- **工作方式：**Git 保存每个可玩的里程碑；每步完成时运行项目启动、关键操作和存档的针对性检查，再更新侧边栏进度。

## 风险与处理

1. **范围失控：**完整设计规模远超单人 MVP。MVP 只验证一个板块内的探索—招募—战斗循环，后续内容按板块分批加入。
2. **美术可用性：**现有生成图是设定／动作参考，方向、像素格与帧锚点未统一。先对试玩角色做人工审校的游戏内精灵，再批量制作其他角色。
3. **系统耦合：**职业切换、AI 和存档相互影响。以稳定 ID 与版本化存档连接数据；M3–M6 每步用小范围情景复查。
4. **转场速度：**独立战斗场地可能产生加载延迟。先采用预加载的小型战斗场景，M3 即测接敌到控制可用的时间。
5. **内容与翻译：**双语内容会随着人物增加而成倍增长。所有 UI／文本从 M1 起使用键值，试玩段只写必要文本。

## 尚待决定，但不阻挡 M1

- MVP 主角开始的具体等级与四条职业的最低技能列表；M5 前决定。
- 可运行精灵格尺寸：先以探索 64×96、战斗 128×128 为候选，M1–M3 用实际画面调整。
- 试玩地点与 NPC 的正式名字；M7 前确定，剧情主线仍留待后续设计。

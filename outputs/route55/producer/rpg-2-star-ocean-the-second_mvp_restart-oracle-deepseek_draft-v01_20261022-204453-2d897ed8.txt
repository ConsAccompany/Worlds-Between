**Pitfalls / false passes**
- Direct `write_manual_save`/`load_save`/`SaveStore` calls, `change_scene`, or scene reload are not a process restart; autoload state survives.
- `_summary` checks only schema, destination, hero level, activeParty size, and note; the screen can look right while party detail, quest flags, bonds, appearance, calendar, and exact position differ.
- `_save` reports success for any nonempty ID; `load_save` returns true after validation/migration, not equality.
- `_latest_manual` loads the first slot match; stale/duplicate ordering can load the wrong ID. Assert the entry ID and schema. A disabled button, schema mismatch, or invalid snapshot means no load happened.
- `load_save` mutates state before `change_scene_to_file`; a failed scene transition can leave correct-looking fields on the old scene.
- Defaults hide omissions: missing `heroAppearance` becomes `male`, missing `annexSurfaceReturnPosition` becomes `[558,143]`, and missing `partyBonds` gain zeroes. Coincidental defaults are not persistence proof.
- Raw equality is not the oracle: `GrowthRules.normalize_member` can mutate `hero`/`members`; receipt, battle, guide, and run fields reset on load.
- `save_return_position` is not proven current; verify the save was taken after movement and that snapshot position matches the observed checkpoint. `resume_annex_position` mirrors `position`, so it is not independent evidence.
- `playTimeSeconds` advances after load; compare saved/immediate values with tolerance.
- Back is not Load: it returns to `save_return_scene` and sets resume flags; it does not read the save.
- Auto-save order/creation is unconfirmed and may overwrite evidence. Calendar fields are unconfirmed, so a clean scene load alone cannot prove calendar correctness.

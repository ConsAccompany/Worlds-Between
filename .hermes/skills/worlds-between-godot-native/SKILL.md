# Worlds Between Godot and native assets
## When to Use
Authoring sprites/scenes, validating editable sources, importing, or capturing actual gameplay.
## Prerequisites
Use the parent project tooling environment (`terminal(command="source ../tooling/worlds-between-env.sh ...")`). Linux Godot4.7.2, Pixelorama1.2.3, Python NumPy/Pillow, FFmpeg and Xvfb are installed.
## Procedure
1. Use `read_file` for the relevant source contract, author and existing checker. Preserve identity, pivot,48logical exploration pixels, palette and protected geometry.
2. Use `terminal` to run existing authors/checkers. Native source, PNG exports and source hashes must match; disclose exact failing predicates.
3. Run every Godot probe with the checked runner and finite deadline. SCRIPT_ERROR, Parse Error or missing expected marker fails even on exit0.
4. Use `terminal` with xvfb-run for real rendered bilingual/gameplay captures and `vision_analyze` on actual files when available. Motion requires normal-speed review of start/run/stop/repress/reversal and battle timing.
5. Keep source production, loader integration, native GUI save/reopen, visual inspection and human acceptance distinct.
## Pitfalls
Headless test passes are not visual proof; source stop bridges are not demonstrated by an immediate-idle host. Do not broaden parameter searches or call residual foot slip footlocked. Known app diagnostics must remain disclosed.
## Verification
Required source/native and targeted gameplay checks pass with source-bound logs; captures actually load, no default changes without creator authorization, no unsupported visual claims.
